**卷积引擎图**

```text
3×3 line/window buffer 或 1×1 pixel buffer
 → activation alignment/broadcast
 → P parallel MAC lanes（各lane：乘法→累加）
 → result bank
 → serialized channel drain
 → +bias
 → activation
 → requantization
 → output FIFO
```

权重 ROM 独立提供 P 个权重至 P lanes。顺序地址控制器控制 ROM 和窗口遍历。

- 原图5的 `activation → weight ROM` 和 `weight ROM → accumulator` 都不正确。
- MAC lane 内已完成累加，后面的 bank 是捕获结果，不能画成无条件再执行另一层累加。

实例：`rtl/gen/blk_rx_in_output.sv:1315`，`dec.7.conv+skip` 为 `CIN=32,COUT=256,P=52,ACT_SPLIT=128`，split 为128/128。

2. **ATT 首层合并**

```text
共享pixel buffer → merged 1×1 conv → channel split → A支路后续
                                          └──────→ B支路后续
```

只合并 `a0.c0` 和 `b0.c0`，没有把整个注意力块合成单引擎。

实例：`rtl/gen/blk_rx_in_output.sv:626`，`dec.0.ab0.c0` 为 `CIN=16,COUT=16,P=1,SPLIT=8`。

3. **残差1×1旁路中心抽头**

```text
3×3窗口流 ─────────────────→ 主路3×3 conv → 后续
       └→ centre_tap → 独立1×1 skip conv → delay FIFO → add
```

此处共享输入窗口读流，**仍有两个独立 conv engines**。原图6把所有三种情况都标 `1 engine`，对该情况是错误的。
