建议按以下几类设计：

| 类别 | 可注入位置 | 示例错误 | 预期症状 |
|---|---|---|---|
| 编译/ elaboration | `bit_source.sv` | 参数位宽写错、端口名拼写错误 | 编译或 elaboration 失败 |
| 帧计数 | `bit_source.sv` | 1914 改成 1913/1915 | 突发长度错误，后级帧边界逐渐错位 |
| 突发控制 | `bit_source.sv` | 间隔计数少一个周期、暂停期间仍保持 `valid` | 帧间空闲长度不对，或出现额外比特 |
| 扰码 | `scrambler.sv` | 修改 LFSR tap、尾零数量改错 | 编码输出与参考比特流不一致 |
| 卷积编码接口 | `tx_baseband_top.sv` | `s_axis_data_tready` 或 `m_axis_data_tready` 接错 | 数据丢失、流水线停顿或死锁 |
| 交织 | `interleaver.sv` | 读写 bank 选择反转、地址查表错位 | QAM 数据可传输，但星座数据错误 |
| QAM | `QAM_mapper.sv` | I/Q 交换、某个 Gray 映射值符号反转 | 星座图镜像、旋转或象限错误 |
| 导频/空载波 | `pilot_insert.sv` | 导频位置偏移一个子载波、符号计数不复位 | 频域波形结构错误 |
| 频域移位 | `fft_ifft_shift.sv` | FIFO/直通选择初值反转 | IFFT 输入频谱左右半区错位 |
| IFFT 配置 | `tx_baseband_top.sv` / `ifft.xci` | CP 长度改为 8、方向位改错 | 时域帧长度错误或波形完全异常 |
| 截位饱和 | `truncation_and_saturation.sv` | I/Q 位选取偏移一位、上下限写错 | 振幅异常、削顶或符号错 |
| 前导/帧边界 | `preamble_insert.sv` | `DATA_LENGTH` 改错、`tlast` 提前/延后 | 帧长度错误，`axis_packet_fifo` 不输出或多输出 |
| 包 FIFO | `axis_packet_fifo.sv` | `packet_cnt` 加减条件错 | 下游一直无 `valid`、只输出半帧或计数溢出 |
| 异步时钟域 | `DAC_controller.sv` | 读使能条件改错、复位极性错误 | DAC 输出全零、重复数据或下溢 |
| Testbench | `tx_testbench.sv` | `ready` 周期性拉低、改变两个时钟频率 | 暴露反压、缓存和 CDC 问题 |

我尤其推荐下面几处作为第一批，因为症状具有代表性：

1. `bit_source` 最后一位判断改成 `BITS_PER_FRAME-2`  
   用于验证 agent 是否能通过波形发现“每帧少一个 bit”。

2. `BURST_GAP_CYCLES` 计数边界改错  
   用于验证是否能区分“帧长度正确但帧间隔错误”。

3. `pilot_insert` 的一个导频位置改动  
   用于验证 agent 是否能从频域结构定位问题，而不是只检查数据有没有流动。

4. `fft_ifft_shift` 的 `mux_select` 初值反转  
   用于验证频谱排列和时域波形分析能力。

5. `preamble_insert` 的 `sample_last` 偏移一拍  
   用于验证 `tlast`、包 FIFO 和帧长度的联动诊断。

6. `axis_packet_fifo` 的 `packet_cnt` 更新条件改错  
   用于验证 agent 对“无输出/死锁”类问题的定位能力。

7. `DAC_controller` 中 `rd_en = ~empty` 改为带错误条件  
   用于验证 agent 是否能识别异步 FIFO 下溢，而不是误判为上游没有数据。

为了验证调试 skill 的效果，建议每个错误都配一个小型“注错记录”，包含：

- 错误编号和修改位置
- 注入的具体错误
- 预期可观察症状
- 最小复现仿真时间
- 正确修复点
- 判断 agent 是否真正定位成功的标准

最好分三档难度：

- 简单：编译错误、明显位宽错误、端口连接错误
- 中等：计数器边界、`valid/ready`、`tlast`、I/Q 符号
- 困难：跨时钟 FIFO、反压传播、只在第二帧出现的状态机错误

此外，建议保留一个干净基线，并让每个错误独立存在。不要一次注入多个相互依赖的错误，否则很难判断 agent 是定位到了根因，还是只修掉了表面症状。
