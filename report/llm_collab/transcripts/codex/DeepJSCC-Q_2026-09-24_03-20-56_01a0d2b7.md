> 修改batch size会带来什么影响吗

**助手：**

会有影响，但当前模型没有 BatchNorm，所以影响主要来自优化过程和吞吐。

### 增大 batch size 的影响

- **梯度更稳定**：每次更新使用更多样本，梯度噪声变小。
- **每个 epoch 的更新次数减少**：例如从 batch=4 改为 batch=8，更新次数约减半。
- **收敛轨迹会变化**：即使 epoch 数相同，参数更新次数不同，最终 PSNR 可能不同。
- **显存增加**：主要增加中间激活，占用仍取决于输入分辨率。
- **吞吐提高**：当前模型较小，batch=8 或 16 通常比 batch=4 更适合 GPU。
- **验证结果本身不受 batch size 直接影响**：验证阶段只是批量推理。

### 对当前项目的建议

当前 batch=4 的 20 轮模型可以作为已有基线。后续建议：

- 默认使用 `batch_size=8`
- 学习率先保持 `2e-4`
- 比较 batch=8 和 batch=16 时，使用相同的数据划分、随机种子和训练轮数
- 不要直接把 batch 改成 32 后宣称与旧模型严格可比

如果希望尽量保持原来的优化行为，可以使用梯度累积。例如物理 batch=8、累积 2 次，相当于有效 batch=16，同时减少显存压力。

**助手：**

这个因子不是交接文档或参考仓库的公式，是我在重写量化器时引入的错误。

正确推导如下。

对于 64-QAM，I/Q 每个分量的未归一化电平为：

\[
\{-7,-5,-3,-1,1,3,5,7\}
\]

均匀分布时：

\[
E[I^2+Q^2]=42
\]

因此复符号平均功率归一化为 1 时，输出电平应为：

\[
\frac{\{-7,-5,-3,-1,1,3,5,7\}}{\sqrt{42}}
\]

论文给出的通用 QAM 公式也得到相同结论：[2022 JSAIT 论文](https://arxiv.org/abs/2206.08100)

参考实现仓库只是 AF 版本 trainer，里面没有为当前 FPGA 结构提供可直接复用的 `sqrt(2/42)` 量化公式：[deepjscc_stream](https://github.com/r0ymanesco/deepjscc_stream)

错误来自混淆了两种 RMS 定义：

- `flat.square().mean().sqrt()` 是**单个实数 I/Q 分量的 RMS**
- `sqrt(I²+Q²)` 是**复符号功率 RMS**

当前代码已经修正为：

1. 先把 encoder 输出除以单实数分量 RMS；
2. 在这个单位 RMS 坐标上寻找最近的 64-QAM 电平；
3. 输出电平再除以 `sqrt(42)`；
4. 不再把输入额外乘 `sqrt(2/42)`。

> 规划定点化方案

**助手：**

下面是定点化方案草案。我先只规划，不修改代码、不启动 PTQ/QAT。

## 1. 总体目标

- 权重：**W8**
- 激活：**A8**
- 卷积乘加：**24 位有符号累加器**
- 偏置加法和舍入：保留 1 位保护位，使用 25 位内部结果，不把它作为 MAC 累加位宽
- 所有重新缩放：只使用**算术移位**
- 零点：全部采用对称量化，zero-point = 0
- 不改变网络结构、latent 数量和 QAM 接口

卷积中最宽的点积是 3×3、输入通道 32：

\[
K=3\times3\times32=288
\]

INT8 最大乘积：

\[
127\times127=16129
\]

最坏累加：

\[
288\times16129=4,645,152<2^{23}
\]

因此，**24 位有符号 MAC 累加足够覆盖最坏乘积和**。偏置加入、四舍五入和饱和需要额外保护位。

## 2. 定点格式

| 对象 | 格式 |
|---|---|
| 输入 RGB | 无符号 8 位，表示 `[0,1]` |
| 权重 | 对称 INT8，按输出通道使用 2 的幂尺度 |
| 中间激活 | 对称 INT8，逐层使用 2 的幂尺度 |
| 偏置 | 保存为与累加器同尺度的有符号定点值，建议至少 25 位 |
| MAC | 有符号 24 位 |
| 重新缩放 | 加偏置后只做算术右移，随后饱和到 INT8 |
| QAM I/Q | INT8，单独使用覆盖 `±7/√42` 的 Q 格式 |
| sigmoid 输出 | 无符号 8 位 LUT |
| GDN/IGDN 输出 | 有符号 INT8 |

权重尺度和激活尺度都限制为：

\[
s=2^k
\]

因此卷积输出只需要：

\[
y=\operatorname{sat8}\left(\operatorname{round}(acc+b)\gg r\right)
\]

不使用浮点乘法，也不使用一般实数乘法做重新缩放。
