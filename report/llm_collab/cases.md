# 大模型协作典型案例

每个案例分"背景、模型做了什么、用户做了什么、结果"四项。出处为 `transcripts/` 下的会话文件与日期（UTC）。

参与者：**用户**（参赛者：提出目标与约束、做关键判断、负责接线 / 上电 / 观察等物理操作）；**Claude Code**（AD9361 / OFDM PHY、
PYNQ 软件、GUI、测量、演示视频、仓库与报告）；**Codex**（DeepJSCC-Q 训练与量化、网络 RTL 生成器与验证、网络部分论文草稿）。

## 一、射频前端与物理层（Claude Code）

### 1. AD9361 配置未真正执行（SPI 握手错位）

- **背景**：单板环回 EVM 只有 −22 dB，原因不明。（`claude/AD9361_fc490b96.md`，09-25）
- **模型**：离线解调抓取的帧，逐项排除噪声、信道、ISI、非线性，按镜像子载波定位到 IQ 失衡；推断 TX 正交校准没有生效，追到 SPI 状态机
  不等请求就锁存命令、应答错位一拍，所有"等待校准完成"的轮询都立即通过；修正后又补上 PL 内的正交校准相位扫描和 FIR 重新设计。
- **用户**：指定 ILA 的触发条件（按数据值触发，避开突发之间的静默区），使抓到的都是有效帧。
- **结果**：EVM −22.0 → −29.7 dB，最终约 −32 dB（`report/notes/ad9361_debug_log.md`）。

### 2. AGC 配置：模块边界与资料核实

- **背景**：两板对收时 AGC 在帧中间跳变。（`claude/AD9361_d69a7c9d.md`，09-26）
- **模型**：先提出用基带的帧检测信号控制 EN_AGC 引脚冻结增益，并开始修改 RX 基带；撤回后改为对照 openwifi 的配置，
  最初只检索了一个关键字，补读 openwifi-hw 与配置脚本后，发现工程的 AGC 寄存器表照抄时漏了 4 项。
- **用户**：否决让 AGC 依赖基带信号（AGC 属于射频模块）；质疑模型对 openwifi 的引用是否完整，要求先读完再下结论。
- **结果**：补齐 4 个寄存器后稳态正常；"AGC 不与基带耦合"成为之后所有 AGC 工作的约束。

### 3. LTF 定时门限

- **背景**：两板空口偶发定时锁到 LTF2 而不是 LTF1，整帧错位。（`claude/AD9361_d69a7c9d.md`，09-26）
- **用户**：判断原因是采样相位偏移（最坏差半个采样点），要求先算出此时的相关主峰与最大旁瓣，门限用移位加法实现。
- **模型**：用实际前导与相关模板计算：半采样偏移时主峰 ρ² 降到 0.54，最大旁瓣 0.29；采用用户建议的 0.375，改为移位加法，
  回放出错数据段仿真验证。
- **结果**：原来锁错的帧全部锁回 LTF1，0 误码；门限沿用到最终版本。

### 4. 长帧的 SFO 跟踪

- **背景**：DeepJSCC-Q 一帧需要 683 个 OFDM 符号，采样频偏在帧尾累积。（`claude/AD9361_d69a7c9d.md`，09-28）
- **用户**：先要求评估最坏 ±20 ppm 下的可传帧长；要求先在自己的 MATLAB 接收机上验证、给出 RTL 资源估计后再改；
  提出用循环移位的 LTF 匹配滤波器代替回看移位寄存器；信道估计只做双 LTF 平均。
- **模型**：设计逐符号导频 LS + 二阶环的 SFO 跟踪，常数乘除改为移位加减，完成 MATLAB、RTL 与仿真。
- **结果**：±40 ppm、683 个符号仿真 0 误码；板上帧尾 EVM 与帧头只差约 1.7 dB。

## 二、网络硬件规划（Claude Code）

### 5. 定点方案的硬约束

- **背景**：确定 DeepJSCC-Q 的定点与非线性实现方式。（`claude/DeepJSCC-Q_e33e691b.md`，09-28）
- **用户**：规定操作数位宽不超过 DSP48E2；平方根 / 倒数用迭代而不是查表；指出 sigmoid 查表会因各层读口独立而大量消耗 BRAM，建议分段线性或 CORDIC。
- **模型**：据此给出 W8A12 方案、整数参考模型与 RTL 结构。
- **结果**：GDN / IGDN 用迭代平方根与除法，sigmoid 用 32 段分段线性。

### 6. 并行度与权重存储

- **背景**：卷积引擎的输出通道并行度 P 与权重 ROM 形状。（`claude/DeepJSCC-Q_d3a7236c.md`，09-29）
- **模型**：先按总容量估算 BRAM，后改为逐层按原语与端口计算；提出"P 取最小值省 DSP、P 按 BRAM 位宽取省 BRAM"的二选一。
- **用户**：指出 BRAM 估算必须考虑读写端口、不同层不能共用；质疑 P 为什么要受 BRAM 位宽限制，提示可用 LUT 做位宽转换。
- **模型（修正）**：意识到权重是严格顺序读取的，ROM 可按 BRAM 最省的形状紧密存放，读出后经位宽转换器输出，所谓取舍并不存在。
- **结果**：DSP 与 BRAM 同时下降：编码器权重 ROM 42.0 → 38.0 BRAM36、乘累加 DSP 255 → 223；解码器 67.0 → 62.5、326 → 298。

### 7. 网络与 PHY 的缓冲划分

- **背景**：网络与 PHY 的接口约定。（`claude/DeepJSCC-Q_d3a7236c.md`，09-29）
- **模型**：在未确认 PHY 是否有缓冲的情况下，自行假设"突发无法反压"，在编码器、解码器两端各加了整帧 FIFO。
- **用户**：指出 PHY 已有帧缓冲，网络两端不应重复，要求改回带反压的标准 AXI-Stream，并给出 24 位 {Q,I} Q10 的接口格式。
- **结果**：省掉 5 个 URAM；该接口成为网络与 PHY 对接的冻结约定。

## 三、网络训练、RTL 与论文（Codex）

### 8. 量化器标定错误

- **背景**：DeepJSCC-Q 重写后的训练。（`codex/DeepJSCC-Q_2026-09-24_*.md`，09-24）
- **用户**：观察到 PSNR 上升明显慢于以往版本，要求排查，并追问错误来源。
- **模型**：统计星座电平分布，发现量化前多乘了 `sqrt(2/42)`，大多数符号挤在中间几个电平；确认是自己混淆了单分量 RMS 与复符号 RMS，
  不是参考资料的写法。
- **结果**：修正后重训，之前的结果作废。

### 9. 累加器位宽

- **背景**：W8A8 / W8A12 全定点规格。（同上，09-24）
- **模型**：先给出 int16 激活、int32 累加的通用默认值。
- **用户**：要求按网络实际最大卷积规模计算所需位宽。
- **模型（修正）**：算出最坏累加值 4,718,592，24 位即够。
- **结果**：RTL 改为逐层按公式配置累加位宽，不再使用固定 32 位。

### 10. 汇合 FIFO 与存储规划

- **背景**：残差 / 注意力分支汇合处的 FIFO 深度与 RAM 用量。（`codex/DeepJSCC-Q-FPGA-docs_2026-09-29_*.md`，09-29 – 09-30）
- **模型**：用仿真测峰值来定 FIFO 深度，RAM 用量等综合结果；综合出 105 BRAM36 + 3 URAM，与规划不符；跨时钟域 FIFO 自行编写。
- **用户**：要求 RAM 用量在综合前由规划算定、综合只用于核对；指出另一支路延迟是确定的，FIFO 深度应能分析；要求直接用 XPM 原语。
- **结果**：规划值编码器 97.5 BRAM36 + 4 URAM、解码器 99.5 + 18；差异原因是汇合 FIFO 未按规划迁入 URAM，修正生成器后与最终 OOC 结果一致；
  跨时钟域改用 `xpm_fifo_axis`。

### 11. 论文的立意与对比口径

- **背景**：网络部分的论文草稿。（`codex/DeepJSCC-Q-FPGA_2026-10-03_*.md`，10-02 – 10-03）
- **模型**：先做了一轮代码审查，随后未确认论文要写什么就直接成稿，没有 PPA 分析，也未注意到本设计与对比论文的网络完全不同。
- **用户**：说明对比论文的用途（参考组织方式、作为对比对象），要求换算成统一的名义 MAC 再比较，重点放在微架构选择对 PPA 的影响。
- **结果**：论文和本报告 4.1、4.5 节都按名义 MAC、资源绝对量与口径边界来写对比。

## 四、系统集成与测量（Claude Code）

### 12. TX 偶发卡住

- **背景**：上板时 TX 偶尔不发射。（`claude/AD9361_d69a7c9d.md`，10-02）
- **模型**：先断定是"数据卡住"并准备改 RTL；用户质疑后改为设计 A/B 实验（加载后不发数据 / 立即发 PRBS），实验否定了自己的第二个猜测；
  另外主动列出两处操作失误（后台进程未重定向 stdin、`pkill -f` 误杀自身 shell）。
- **用户**：质疑结论缺乏证据，提供关键观察（卡住期间指示灯一直不亮）；决定不改 RTL、不加软件控制，先打通端到端链路。
- **结果**：用"重新加载"规避，端到端图像链路打通，板上 PSNR 与仿真一致；根因记录在案，未继续追查。

### 13. 显示问题：模型无法观测硬件时的局限

- **背景**：触摸屏经 Mini DP 转 HDMI 不显示。（`claude/AD9361_d69a7c9d.md`，10-04 – 10-05）
- **模型**：依次尝试显示模式、HDMI OUT 自建工程、官方 overlay、对照原理图，最后建议购买另一种转接头；被用户指出缺乏依据后，改为提出零成本的对照实验。
- **用户**：完成所有接线和观察，否决了没有证据的购买建议。
- **结果**：更换屏幕后正常显示。在模型看不到物理现象时，它容易连续给出未经验证的假设，花钱的建议尤其需要证据。

### 14. AGC 看门狗的判据

- **背景**：AGC 在信号变弱后偶尔停在低增益，链路中断。（`claude/AD9361_caed093a.md`、`claude/DeepJSCC-Q_f63b5e40.md`，10-06 – 10-07）
- **模型**：最初用 RSSI / 底噪门限判断"增益卡住"，因底噪读数随环境漂移，三次修改后仍误复位；之后又因一次复测超过自己设定的 2.5 s 而回退了另一项修复。
- **用户**：要求不依赖随信道变化的绝对门限，把问题化简为"AGC 没跟上会导致同步失败"；指出模型自定的经验阈值不是规格。
- **结果**：改为"同步率 + 增益"判据（只读 PL 计数器，不碰基带），验收通过（`report/notes/agc_notes.md`）。

### 15. SSCC 悬崖区异常

- **背景**：SSCC 的 PSNR–SNR 曲线在悬崖区不单调。（`claude/DeepJSCC-Q_f63b5e40.md`，10-07）
- **模型**：排查测量方法进展缓慢；之后提出关闭过载解锁（会影响其他场景）、误称大过载没有计数器、只单独调一个过载门限就排除了 ADC。
- **用户**：指出方向（SSCC 没有星座熵约束，PAPR 更高，可能触发过载解锁），要求计算两者的 PAPR；指出多个过载检测是"或"的关系，必须组合测试；
  要求修改前评估对其他功能的影响，修改后实测 SNR。
- **结果**：确认是大 ADC 过载；AGC 锁定电平 −12 → −14 dBFS，台阶帧 9/45 → 0/44，SNR 提高 0.1–1.9 dB。

### 16. 测量口径的公平性

- **背景**：时延与帧率的测量方法。（`claude/DeepJSCC-Q_f63b5e40.md`，10-07）
- **模型**：在 PS 上按图像到达时间统计时延和帧率，并把 SSCC（JPEG 在 PS 上）一并比较。
- **用户**：指出 PS 调度抖动不应计入 FPGA 指标、SSCC 的时延比较不公平，要求参照 GLOBECOM 2025 论文的测法。
- **结果**：改为两板轮询 PL 帧计数器、按数据流配对，按论文分三段（编码 38.20 / 传输 2.87 / 解码 30.39 ms）；SSCC 只比较画质。

## 小结：分工模式

| 环节 | 用户 | 模型 |
|---|---|---|
| 目标与约束 | 指标（30 fps、683 符号帧、W8A12、DSP48E2 位宽）、模块边界（AGC 不碰基带、缓冲归 PHY）、公平的测量口径 | 把约束落实为方案并估算资源 |
| 关键判断 | 半采样相关峰、PAPR 与熵约束、过载条件的"或"关系、顺序读权重可用位宽转换 | 推导、计算、实现与验证 |
| 证据 | 物理观察（指示灯、屏幕、天线）、接线与上电 | 抓数据、写测量脚本、做 A/B 实验、出图 |
| 纠错 | 追问依据，否决缺乏证据的结论与超出范围的改动 | 承认、撤回、补测，把教训写入记忆与文档 |

模型反复出现的问题：没有证据就下结论、把自己定的经验值当规格、没有问清约束就自行增加设计、只看了部分资料就引用。
对应的协作约定（改动要小而有判据、一次只改一处、先定验证标准、不要无必要改 RTL）见交接文档与 `report/notes/`。
