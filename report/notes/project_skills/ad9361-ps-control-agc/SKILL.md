# AD9361：初始化从 PL 查找表迁到 PS，快速 AGC 的配置、排查与看门狗

## 适用场景

- AD9361 由 PL 里的状态机按 ADI Evaluation Software 生成的寄存器表初始化（"纯 PL"方案），调 AGC 等参数要改 RTL、重编比特流。
- 突发 OFDM 接收（帧占空比低，例如 2.75 ms / 33 ms），用快速攻击（fast attack）AGC：
  - 信号突然变弱后 AGC 停在低增益，PHY 同步不上；
  - 或者帧中间出现增益台阶（整帧 EVM 突变），尤其是峰均比高的波形。

## 使用方法

### 1. 初始化迁到 PS（不改配置内容）

1. 在 PL 里保留 SPI 主机，只加一个 PS 可写的命令寄存器：`SPI_CMD = {rd(25), wr(24), data[17:10], addr[9:0]}`，
   `SPI_STAT = {完成计数[15:8], 读数据[7:0]}`（计数变化即完成），外加 `RF_CTRL` 控制 RESETB / PS 模式 / 初始化完成（释放数据通路）。
2. 用 `src/sw/tools/lut_to_json.py` 把 PL 查找表转换成 JSON 操作序列：`w`（写）、`r`（读）、`poll`（读直到 `& mask == want`，
   对应校准完成、PLL 锁定等等待）、`delay`。**转换结果先和原表逐条比对**，确认只差你有意修改的项。
3. PS 端 `src/sw/rx/ad9361_ps.py` 的 `AD9361.init()` 执行序列；`rd/wr` 用于运行时读写，`agc_dump()` 打印全部快速 AGC 寄存器。

### 2. 快速 AGC 配置与排查

- **起点**：openwifi `agc_settings.sh` 的优化值（`0x15C=0x70, 0x106=0x77, 0x103=0x1C, 0x101=0x0C, 0x110=0x48, 0x114=0xB0, 0x115=0x80`），
  最后 `0x0FA` 写 `0x05` 再写 `0xE5` 复位 AGC 状态机。照抄时逐项核对，不要漏。
- **读状态**：快速 AGC 状态在 **`0x2B3[2:0]`（5 = 增益锁定）**；`0x0A7` 是 TX 正交校准状态，不是 AGC。当前增益索引 `0x109` / `0x2B0`。
  需要逐采样观察时，把 CTRL_OUT 指针（`0x035`）设为 `0x16`（增益锁定 + 增益索引）或 `0x07`（过载标志 + AGC 状态），在 PL 里采样 CTRL_OUT。
- **锁定态（state 5）的三类解锁条件**：能量丢失（`0x110[D3]`）、更强信号（`0x115[D7]`）、大 ADC / 大 LMT 过载（`0x110[D1]=0` 时启用）。
  帧中台阶几乎总是其中之一触发。**多个检测器是"或"的关系**：只调高其中一个门限、台阶还在，只能说明"至少还有另一个在触发"，
  必须两两组合测试（2×2 表）才能定位。
- **过载用计数器累计**：大 LMT / 大 ADC 过载要累计超门限若干次（`0x121 / 0x122` 的计数，本例 14 次）才动作；门限读 `0x105`（ADC）、`0x108`（LMT）。
- **修复优先降锁定电平**（`0x101`），给峰均比留余量，而不是放宽或关闭过载保护：后者在信号小幅变强时会让 AGC 锁在偏高增益、削顶且不恢复。
  改完必须测 SNR（降电平可能提高也可能降低 SNR，要用数据说话）。
- 判断 LMT 是否可能触发：按当前增益表推算 LMT 处与 ADC 处的电平差（本例增益档 57 时 LMT 处低约 16 dB，LMT 不是原因）。

### 3. 卡住看门狗（不依赖绝对门限）

AGC 停在过低增益的直接后果是 **PHY 同步不上**。所以只读 PL 的同步计数器和当前增益：

```
若 0.5 s 内同步帧增长 < 5 帧/s 且 增益索引 < 增益表上限 → 复位 AGC（0x0FA: 0x05 → 0xE5）；两次复位至少间隔 3 s
```

- 不用 RSSI、底噪、帧功率等绝对门限：这些读数随环境、AGC 状态和采样时机漂移。
- 计数器读取不要和其他 SPI 访问共用长时间持有的锁（否则恢复被拖慢到数秒），只有 SPI 复位时拿锁。
- 无信号时增益停在表上限附近以下，会每 3 s 复位一次，无害；信号恢复后立即同步。
- 实现：`src/sw/rx/ad9361_ps.py` 的 `AgcGuard`；验收脚本 `board/tests/agc_guard_test.py`。
- 发射端减小信号时用斜坡（本例 10 dB/s），可明显降低卡住的概率。

## 已验证效果

- PL 表 → JSON 转换：1728 条操作与原表逐条一致，只差有意修改的 `0x101`；RX 板由 PS 初始化，约 25 s 完成（含比特流下载）。
- 看门狗（`report/notes/agc_notes.md`）：0 dB 静置 180 s 误复位 0 次；衰减 4 → 24 dB 跳变 6 次全部恢复（1.05–2.36 s）；无信号时恢复正常。
- 锁定电平 −12 → −14 dBFS：SSCC（无星座熵约束、PAPR 尾部高约 0.8 dB）台阶帧 9/45 → 0/44，各衰减点数据辅助 SNR 提高 0.1–1.9 dB。

## 来源（从哪次失败中总结）

- 照抄 openwifi 的 AGC 配置时只搜了一个关键字就下结论，漏了 4 个寄存器（`report/llm_collab/cases.md` 案例 2）。
- 基于"按 SPI 触发采 RSSI"的看门狗：帧占空比 8 %，采样经常落在帧间隙读到底噪；底噪读数又随环境在门限两侧摆动，导致 0 dB 下每 1–2 分钟误复位、
  真正卡住时 14–17 s 才恢复。改了三次门限都失败后，换成"同步率 + 增益"判据（案例 14）。
- 读 `0x0A7` 当作 AGC 状态，实为 TX 正交校准状态。
- SSCC 悬崖区整帧随机失败：先只单独调一个过载门限就断定"不是它"，后来按"或"逻辑做 2×2 表才确认是大 ADC 过载（案例 15）。
